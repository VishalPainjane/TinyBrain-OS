## 1. Version

V0.4 — Runtime (stub InferenceProvider)

## 2. Goal

Prove the `ModelRuntime` / `InferenceProvider` hexagonal boundary before real llama.cpp integration. Ship a runtime shell with stub provider, lifecycle events, and model swap via the runtime API.

Source: [planning/releases/v0.4.md](../releases/v0.4.md), [docs/specs/v0.4-runtime.md](../../docs/specs/v0.4-runtime.md)

## 3. What Went Well

- `ModelRuntime` interface and shell implementation shipped with full unit test coverage ([completed.md](../execution/completed.md) task 008, commit `bb0b148`).
- `StubProvider` enabled model A → B swap demo without CGO or llama.cpp ([planning/releases/v0.4.md](../releases/v0.4.md)).
- `ModelLoaded` / `ModelUnloaded` events integrated with existing event bus (ADR-003).
- Month 2 adjacent work (009 stub loader, 010 FIFO scheduler) completed without violating INV-001 — scheduler imports only `internal/process` ([planning/releases/v0.4.md](../releases/v0.4.md)).
- `Queue` interface behind scheduler preserves FIFO → MLFQ migration path ([planning/releases/v0.4.md](../releases/v0.4.md) lessons learned).
- Separating scheduling policy from runtime orchestration unblocked parallel skeleton work.

## 4. What Went Wrong

- `Schedule()` signature drift: contract documents `Schedule() error`; implementation returns `(process.Process, error)` ([task-010-schedule-signature-drift.md](../decisions/task-010-schedule-signature-drift.md)).
- Parallel lifecycle state in `StubProvider` and `StubLoader` with no wiring between them ([planning/releases/v0.4.md](../releases/v0.4.md) known issues).
- Runtime contract still marked "not yet implemented" in [docs/contracts/runtime.md](../../docs/contracts/runtime.md) despite shipping.
- [planning/architecture-evolution/current-state.md](../architecture-evolution/current-state.md) not updated after ship — lists runtime as "not started".
- No end-to-end scheduler → runtime → generate path (intentionally deferred).

## 5. AI Mistakes

- Early task documentation referenced fixed agent names (Planner, Coder) conflicting with plugin architecture — corrected during Month 1 ([planning/retrospectives/week-1.md](../retrospectives/week-1.md)).
- Contract drift documented in planning rather than reconciled at ship time — acceptable per task 010 rationale but increases reader confusion.

## 6. Architecture Mistakes

- Dual lifecycle tracking (`StubProvider` loaded set vs `StubLoader` state machine) without an orchestration owner — deferred integration creates ambiguity for v0.6 ([planning/releases/v0.4.md](../releases/v0.4.md)).
- Loader mmap ownership vs inference provider ownership not resolved at v0.4 — both packages exist independently.

## 7. Planning Mistakes

- v0.4 release bundles tasks 008 (spec scope) with 009 and 010 (Month 2 adjacent) — version tag covers runtime spec but release notes must distinguish spec vs adjacent work to avoid acceptance confusion.
- Contract layer lagged implementation — documented as intentional for task 010 but not closed.

## 8. Technical Debt Introduced

- `Schedule()` contract vs implementation mismatch ([task-010-schedule-signature-drift.md](../decisions/task-010-schedule-signature-drift.md)).
- Runtime ↔ loader unwired; duplicate model lifecycle state.
- Scheduler ↔ runtime orchestration deferred.
- Stale `current-state.md` and runtime contract "not yet implemented" flag.
- KV manager, swap manager, persistent registry (all explicitly deferred).

## 9. Technical Debt Removed

- None specific to v0.4 — v0.4 introduced new packages rather than retiring prior debt.

## 11. What To Repeat

- Ship stub implementation behind stable interface before external dependencies (Migration Path 2 steps 1–2).
- Lock interface in code first; document contract drift in `planning/decisions/` when intentional.
- Table-driven tests with swap/regression scenarios ([internal/runtime/runtime_test.go](../../internal/runtime/runtime_test.go)).
- Keep scheduler free of runtime imports during skeleton phase (INV-001).

## 12. What To Avoid

- Bundling adjacent tasks into version narrative without labeling spec vs out-of-spec scope.
- Leaving `current-state.md` stale after ship — breaks recovery workflow in AGENTS.md.
- Assuming loader and provider lifecycle will merge automatically without an explicit integration task.

## 13. Lessons For Next Version

- Wire runtime to persistent registry before real inference (deferred to v0.5/v0.6 per [planning/releases/v0.4.md](../releases/v0.4.md) future work).
- Resolve loader vs provider mmap ownership before CGO work ([docs/research/llama-cpp-notes.md](../../docs/research/llama-cpp-notes.md)).
- Update `current-state.md` and contract status as Tier A/B checklist items on every ship ([planning/roadmap/update-checklist.md](../roadmap/update-checklist.md)).
- Read this postmortem before starting v0.6 Phase 1 (Task 009a).
