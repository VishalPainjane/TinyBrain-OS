## 1. Version

V0.5 — Model Registry (persistent metadata)

## 2. Goal

Persistent model metadata — definitions survive process restart. Adapter swap behind existing `ModelRegistry` API without changing scheduler, runtime, or loader.

Source: [planning/releases/v0.5.md](../releases/v0.5.md), [docs/specs/v0.5-model-registry.md](../../docs/specs/v0.5-model-registry.md)

## 3. What Went Well

- `ModelStore` interface with `InMemoryStore` and `BboltStore` shipped; public API preserved ([planning/releases/v0.5.md](../releases/v0.5.md)).
- Migration Path 3 executed: adapter swap without caller changes ([planning/architecture-evolution/migration-paths.md](../architecture-evolution/migration-paths.md)).
- `models.yaml` seed-on-empty bootstrap avoids overwriting user registrations ([planning/decisions/accepted.md](../decisions/accepted.md)).
- bbolt choice recorded in accepted decisions with justification vs stdlib ([006-registry-persistence-architecture-review.md](../decisions/006-registry-persistence-architecture-review.md)).
- INV-004 preserved; scheduler, runtime, loader untouched ([planning/releases/v0.5.md](../releases/v0.5.md)).
- Architecture review completed before implementation — backend, serialization, and boundaries approved upfront.
- All v0.5 spec acceptance criteria met per [docs/specs/v0.5-model-registry.md](../../docs/specs/v0.5-model-registry.md).

## 4. What Went Wrong

- `BboltStore.ListModels` returns `nil` on gob decode failure instead of surfacing corruption ([planning/releases/v0.5.md](../releases/v0.5.md) known issues).
- Gob encoding has no schema version — future `ModelDefinition` field changes need migration tooling.
- No update/delete API for model definitions (register-only).
- Runtime ↔ persistent registry wiring still deferred to v0.6 ([planning/releases/v0.5.md](../releases/v0.5.md) deferred features).
- Hardware-profile filtering of model list not implemented (optional v0.3 enhancement).

## 5. AI Mistakes

- Execution docs incorrectly targeted task 011 (KV manager) for v0.5 persistence work — realigned during architecture review; 011 belongs to Month 3 after v0.7 MLFQ ([006-registry-persistence-architecture-review.md](../decisions/006-registry-persistence-architecture-review.md)).
- Risk of conflating model metadata persistence with KV block storage — separated in review boundaries.

## 6. Architecture Mistakes

- None shipped in v0.5 scope — boundaries held. Latent issue: `ListModels` error semantics weaker than `GetModel` for corrupt stores (known, deferred).

## 7. Planning Mistakes

- Contract and spec should ship with implementation to avoid execution drift — lesson recorded in [planning/releases/v0.5.md](../releases/v0.5.md); partially addressed via pre-code architecture review for 006.
- Month 2 Week 6 roadmap listed "BoltDB or SQLite — TBD" until decision gate closed ([planning/roadmap/months/month-02.md](../roadmap/months/month-02.md)).

## 8. Technical Debt Introduced

- `ListModels` silent failure on corrupt gob entries (contract change deferred to v0.6+).
- Gob schema versioning absent.
- Register-only model API (no update/delete).
- Runtime still does not read persistent registry for load paths.
- Unified `Registry` facade still deferred (RFC-004).

## 9. Technical Debt Removed

- In-memory-only model definitions lost on restart — resolved by `BboltStore` and `NewBboltModelRegistry`.
- Month 1 single-map `ModelRegistry` without store abstraction — resolved by `ModelStore` interface extraction.

## 11. What To Repeat

- Pre-code architecture review with approval checklist before CGO or new dependencies ([006-registry-persistence-architecture-review.md](../decisions/006-registry-persistence-architecture-review.md) pattern).
- Adapter swap preserving public API (Path 3).
- Seed-on-empty bootstrap for first-run UX.
- Log tactical decisions in [accepted.md](../decisions/accepted.md) before merge.
- `go test ./internal/registry/...` as version demo command.

## 12. What To Avoid

- Starting wrong task number (011 vs 006) without cross-checking [docs/current.md](../../docs/current.md) and sprint.
- Adding persistence logic outside `internal/registry/` (INV-004).
- Changing `ListModels` signature without explicit contract approval.
- Assuming runtime will auto-discover bbolt path without explicit v0.6 wiring task.

## 13. Lessons For Next Version

- v0.6 Task 009a must inject `ModelRegistry` for `modelID` → `Path` resolution — v0.5 only stores metadata ([planning/releases/v0.5.md](../releases/v0.5.md) future work).
- Run dependency approval gate before llama.cpp CGO (same pattern as bbolt approval).
- Read [v0.4 postmortem](v0.4.md) dual-lifecycle issue — do not duplicate mmap ownership in loader and inference adapter.
- Contract-quality tests for corrupt store handling remain backlog — do not block 009a but do not forget.
- Read this postmortem before Task 009a implementation.
