# Release V0.5 — Model Registry

**Status:** Shipped (tag `v0.5`)

## Goals

Persistent model metadata — definitions survive process restart.

## Implemented Features

### V0.5 spec scope (task 006-registry-persistence)

- `ModelStore` interface with `InMemoryStore` and `BboltStore`
- bbolt persistence (`go.etcd.io/bbolt`); bucket `models`; gob-encoded `ModelDefinition` per ID
- `NewBboltModelRegistry(dbPath, seedPath)` factory
- `models.yaml` seed format — loads only when store is empty
- `ModelRegistry` API preserved: `RegisterModel`, `GetModel`, `ListModels`; `Close()` added for bbolt lifecycle

## Deferred Features

- Agent registry persistence (agents remain in-memory)
- Tool registry
- Hardware-profile filtering of model list (optional v0.3 enhancement)
- Runtime ↔ persistent registry wiring (v0.6)
- Unified `Registry` facade (RFC-004)
- Hugging Face integration, automatic model download

## Known Issues

- `BboltStore.ListModels` returns `nil` on gob decode failure instead of surfacing a corruption error. `GetModel` wraps decode errors correctly. Callers cannot distinguish an empty store from a corrupt entry via `ListModels` alone. Fix deferred: requires `ListModels() ([]ModelDefinition, error)` contract change (proposed v0.6+).
- Gob encoding has no schema version — field changes to `ModelDefinition` may require migration tooling before fleet configs ship.
- No update/delete API for model definitions (register-only).

## Lessons Learned

- `ModelStore` adapter swap preserved v0.2 API while enabling bbolt without touching runtime or scheduler
- Seed-on-empty avoids overwriting user-registered models on restart
- Contract and spec should ship with implementation to avoid execution drift (see task 011 misalignment)

## Architecture Impact

- `internal/registry/` — `ModelStore`, `BboltStore`, `LoadModelsYAML`; agents unchanged
- Dependencies: `go.etcd.io/bbolt`, `gopkg.in/yaml.v3` (seed parsing only)
- INV-004 preserved; scheduler, runtime, loader untouched
