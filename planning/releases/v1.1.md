# TinyBrain OS v1.1 Release Notes

**Date**: 2026-07-09
**Tag**: `v1.1`

TinyBrain OS v1.1 marks a massive leap toward production maturity, shifting our focus from pure single-node execution to highly optimized, scalable, and memory-safe enterprise deployment.

## Key Highlights

### 1. Zero-Copy Inference & Memory Safety
- **Scheduler Cancellation & Disconnect Hardening**: Overhauled the concurrency model inside `internal/scheduler/v2` to process context cancellations sequentially within the engine tick loop via a non-blocking `CancelChan`. This completely eradicated race conditions and memory leaks that previously crashed the server during abrupt HTTP disconnects.
- **Continuous Prefix Caching (RadixAttention)**: Replaced naive memory allocation with a Radix Trie-backed `PrefixCache`. The scheduler now implements zero-copy physical block sharing for incoming sequences that share common system prompts, dramatically bypassing redundant CUDA prefill computations.

### 2. KV Cache Compression Pipeline
- **Zstandard Data Plane**: Simulated the physical VRAM-to-RAM block swap by integrating `github.com/klauspost/compress/zstd`. The system generates structured dummy tensor payloads, dynamically compresses/decompresses them during Tier movement, and emits precise latency and compression ratio metrics via the Event Bus (`TypeKVCompressed`, `TypeKVDecompressed`).

### 3. Native Enterprise Compatibility
- **OpenAI API Compatibility (`/v1/chat/completions`)**: Realigned the HTTP interface to serve Server-Sent Events (SSE) that flawlessly match the OpenAI specification. TinyBrain can now be plugged directly into LibreChat, Continue.dev, and other ecosystem tools without a proxy.
- **CLI Upgrades**: Implemented the `tinybrain models pull` command to seamlessly download and register GGUF models directly from the command line.

### 4. Kubernetes Fleet Orchestration
- **Production Helm Chart**: Upgraded the `cmd/operator` deployments from basic Kustomize scripts to a fully production-ready Helm chart located at `deploy/helm/tinybrain-operator`.
- **Observability and Resilience**: The Helm chart natively configures `--leader-elect`, bundles custom CRDs, wires up RBAC `ClusterRoles`, and exposes the controller-runtime metrics endpoint (`:8080`) while enforcing `livenessProbe` health checks.

## E2E Testing Notes
All sub-systems have been thoroughly tested locally using `CGO_ENABLED=0` to ensure the Go control plane logic remains perfectly deterministic and independent of the C++ data plane. The concurrency model has been battle-tested against simulated multi-client disconnects, ensuring the CUDA context remains fully isolated from goroutine state panics.
