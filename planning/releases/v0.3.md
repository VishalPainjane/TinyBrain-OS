# Release V0.3 — Hardware

**Status:** Shipped (tag `v0.3`)

## Goals

Hardware probe and profile classification for adaptive model selection. Month 1 foundation release.

## Implemented Features

- RAM detection (GlobalMemoryStatusEx on Windows, /proc/meminfo on Linux)
- VRAM detection via nvidia-smi when available
- CPU info via runtime metrics
- Backend detection: CUDA (nvidia-smi), Metal (Darwin inference), CPU fallback
- Profile classification: Tiny, Standard, Workstation
- Month 1 kernel, events, and registry (v0.1 + v0.2 scope) in same release

## Deferred Features

- ROCm detection
- Boot stdout CLI probe (`cmd/`)
- Model assignment based on profile (registry v0.5+)
- User profile override

## Known Issues

- Windows VRAM unreliable without nvidia-smi in PATH (see planning/assumptions.md)
- Metal backend inferred on Darwin without dedicated VRAM probe

## Lessons Learned

- Classification logic is fully testable via injected `ProbeResult` values
- Honest single foundation commit preferred over fabricated per-task git history

## Architecture Impact

- `internal/hardware/` exposes `ProbeAndClassify()` for registry and runtime (Month 2+)
- Repository governance frozen in `.cursor/rules/` + CI workflow

## Future Work
