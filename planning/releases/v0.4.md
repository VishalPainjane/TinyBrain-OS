# Release V0.4 — Runtime

**Status:** Shipped (tag `v0.4`)

## Goals

Runtime shell with stub InferenceProvider — prove ModelRuntime boundary before real inference.

## Implemented Features

### V0.4 spec scope (task 008)

- `ModelRuntime` interface and shell implementation
- `StubProvider` with canned structured `Generate` responses
- Stub load/unload and model A → B swap via runtime interface
- `ModelLoaded` / `ModelUnloaded` event emission on lifecycle changes

### Month 2 adjacent (outside v0.4 spec features)

- Stub model loader with lifecycle states, warm/prefetch/evict, LRU eviction shell (009)
- FIFO scheduler policy skeleton — queue, selection, state transitions only (010)

## Deferred Features

- Real llama.cpp / GGUF inference (v0.6)
- MLFQ scheduler Q0–Q3, token quantum, boost/aging (v0.7)
- Scheduler ↔ runtime integration (orchestration task)
- Runtime ↔ loader integration
- `Schedule()` contract reconciliation ([task-010-schedule-signature-drift.md](../decisions/task-010-schedule-signature-drift.md))
- KV manager, swap manager (tasks 011+)
- Persistent model registry (v0.5)
- End-to-end generate via scheduler → runtime → provider

## Known Issues

- `Schedule()` implementation returns `(process.Process, error)`; contract documents `Schedule() error`
- Parallel in-memory lifecycle tracking in runtime `StubProvider` and loader `StubLoader` until wired
- Scheduler does not call runtime by design in task 010

## Lessons Learned

- Separating scheduling policy from runtime orchestration preserves INV-001 without blocking FIFO skeleton work
- `Queue` interface behind scheduler preserves FIFO → MLFQ migration path
- Document contract drift in planning when implementation intentionally leads the contract layer

## Architecture Impact

- `internal/runtime/` — ModelRuntime moat; only package that will invoke inference providers
- `internal/loader/` — stub loader; future mmap adapter at v0.6
- `internal/scheduler/` — FIFO policy only; imports `internal/process` only
