# Release V0.2 — Registry

**Status:** Shipped (bundled in tag `v0.3`)

## Goals

In-memory agent and model registry with plugin definitions without hardcoded roles. Event core for decoupled communication.

## Implemented Features

- AgentDefinition register/get/list (`AgentRegistry`)
- ModelDefinition register/get/list (`ModelRegistry`)
- 13 core event types with typed payloads
- Channel-based `EventBus` with interface for future NATS swap

## Deferred Features

- ToolDefinition registry
- Unified `Registry` facade (see RFC-004)
- BoltDB/SQLite persistence (v0.5)
- Hardware-aware model filtering
- Sample fleet test fixture

## Known Issues

- Event delivery ordering not guaranteed (see RFC-005, planning/decisions/accepted.md)
- `Subscribe()` returns unsubscribe func — not a separate `Unsubscribe` method (accepted)

## Lessons Learned

- Separate agent and model registries keep task scope clean
- Event bus v1 uses async goroutine dispatch

## Architecture Impact

- `internal/events/` owns typed lifecycle events and pub/sub
- `internal/registry/` owns agent and model definitions (INV-004 partial)

## Future Work

- Registry facade composing agent + model + tool registries
- Tool definitions and registration
